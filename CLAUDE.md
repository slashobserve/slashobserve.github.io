# SlashObserve site

This repo is the SlashObserve marketing site and docs, served from GitHub Pages at slashobserve.com.
Docs content is written in the core repo `slashobserve/slashobserve` under `docs/` and synced in at build time.

## Commands

| Purpose | Command |
| --- | --- |
| Install | `bun install` |
| Dev server | `bun run dev` |
| Sync docs, schema and corpus (runs before dev and build) | `bun scripts/prebuild.ts` |
| Build (prebuild, `astro build`, Pagefind) | `bun run build` |
| Type check (`astro check`) | `bun run check` |
| Internal link check over `dist/` | `bun run check:links` |
| Unit tests (`bun test`) | `bun run test` |
| Build in a worktree | `SLASHOBSERVE_CORE_DIR=<core checkout> bun run build` |

## Layout

- `src/pages/`: home, /grafana, /features, 404, the /docs/ landing page, `og/[card].png.ts` for marketing social cards and `og/docs/[...slug].png.ts` for one card per docs page.
- `src/components/site/`: shared header, footer, wordmark, theme toggle, halo, page hero and closing frame.
- `src/components/home/`: home page sections.
- `src/components/grafana/` and `src/components/features/`: those pages' sections.
- `src/components/docs/` and `src/components/ui/`: the docs shell, sidebar, TOC, search and pager.
- `src/layouts/`: page layouts.
- `src/lib/`: pure helpers.
- `src/lib/client/`: browser helpers for copy buttons, heading anchors, mounting and scroll lock.
- `src/lib/og/`: the social card registry, colours and renderer (Satori and resvg, fonts from `@fontsource/geist`).
- `src/styles/tokens.css`: the only colour definitions.
- `scripts/`: the prebuild (docs sync, schema, corpus, generated reference), the reference generators in `scripts/reference/`, and the link check.
- `public/CNAME`: the custom domain.
- `core-ref.txt`: the core repo ref the docs are built from.
- `src/content/docs/`, `public/schemas/` and `src/generated/`: generated by the prebuild, git-ignored, never edited by hand.

## Core repo

The prebuild reads the core repo from `SLASHOBSERVE_CORE_DIR`, else `../slashobserve`, copies `docs/**/*.md` into `src/content/docs/` with relative `.md` links rewritten to site URLs, and dates each page from core's git history (skipped on a shallow clone).
The prebuild also writes the ObserveSpec reference into `src/content/docs/reference/observespec/` from core's schema and `spec/examples/`, and the HTTP API reference into `src/content/docs/reference/api/` from core's `api/openapi.yaml` and `api/paths/`; those pages set `generatedFrom`, `navLabel` and `order`, which core pages must not set.
Every core docs page has front matter with `title` and `description`, no body `#` heading, and relative `.md` links.
CI checks out the ref in `core-ref.txt` into `.core/` with the `CORE_REPO_TOKEN` secret.
Never hand-write docs pages in this repo; a docs change is a change to the core repo's `docs/`.

## Content rules

- No milestone names anywhere on the site.
- Numbers about the product come from generated data or the synced schema, never typed by hand.
- Importer numbers on /grafana come from `src/generated/import-corpus.json`, which the prebuild builds from the core goldens in `pkg/grafana/testdata/golden`.
- /features lists only what core main ships; add an item when its feature merges.
- The canvas's `[N]` placeholders stay out of the page until a generator fills them.
- No analytics, cookies or third-party requests; fonts are self-hosted.
- No pricing, enterprise or blog pages.

## Design rules

- Colours only through the tokens in `src/styles/tokens.css`, never a raw hex in a component.
- Light and dark both work through `data-theme` on `<html>` and the `slashobserve-theme` localStorage key.
- Primary buttons use `--primary` (black in light mode).
- The palette is monochrome: `--brand` and `--brand-text` are ink (near black in light, near white in dark) and serve focus rings, eyebrows, icon chips and the step indicator; a unit test keeps them neutral grey and holds focus rings to 3:1 and small text to AA.
- The wordmark slash takes the text colour, never an accent.
- Blue appears only as chart series colours (`--s1`) in product depictions; status colours and code highlighting keep their hues.
- Dark sections use `--band-bg`, `--band-code` and `--band-line` with `--ink-*` text, so they stay visible in dark mode; focus rings inside them use `--ink-fg`.
- `src/styles/marketing.css` is wrapped in `@layer site`, so unlayered component styles win over it without specificity tricks.
- The header has two navs built from `headerNav(links)`: the desktop nav, hidden at 860px and below, and a phone menu panel opened by the hamburger.
  A new nav item shows in both, each link with `aria-current="page"` on its own page.
- Never use gradient-filled text or buttons, backdrop blur, numbered section labels, emoji, stock illustrations or coloured left-border callouts.
- Docs stay calm: flat background, 1px borders.
- Tailwind utilities appear only in the docs components.
- The marketing pages (home, /features, /grafana, 404) share the home's design language; the Website design canvas at `../docs/site/canvas/project/*.dc.html` is no longer their layout spec, and its copy is data.
- Shared marketing styles live in `src/styles/marketing.css`: `.section-y` spacing, the `.h2` scale, opt-in `data-reveal` (run by `MarketingLayout`), `.band-muted` and `.band-ink`; `src/components/site/PageHero.astro` opens a page and `Finale.astro` closes it. A redesign keeps every line of copy and every link.
- The docs follow their own design in the site's brand, not the canvas.

## Code rules

- TypeScript strict.
- React only for islands that need state (`client:visible`); everything else is `.astro`.
- No comments or docstrings in code; shebangs and tool pragmas are the exception.
- Never use an em dash in code, copy or docs.
- Bun is the only package manager, and every dependency is pinned to an exact version.

## Testing and gates

- Unit tests with `bun test` for pure logic only: path mapping, link rewriting and front matter checks, docs dates, link checking, sidebar ordering and prev/next, generated reference pages, link resolution, table scroll, code figure, agent text, loop state, corpus summaries, the feature list, nav, token contrast, docs landing sections and the social card registry and docs card mapping.
- No e2e or visual tests.
- Before calling work done, run `bun run build`, `bun run check`, `bun run check:links` and `bun run test`.

## Commits

- Atomic commits.
- Messages describe the change, with no plan or milestone numbers and no co-author trailers.
